# LUCKY · 现场抽奖系统

[![License](https://img.shields.io/badge/License-Apache%202.0-blue.svg)](LICENSE)

面向现场活动的抽奖系统：**参与者扫码验证 → 主持人控奖开奖 → 手机刮卡 → 大屏同步揭晓 → 结果留档导出**。

适合年会、门店促销、发布会等需要「真实身份 + 现场仪式感 + 事后可查」的场景。

零依赖、单进程、本地运行，不需要联网、不需要数据库账号。Node.js 18+ 即可。

---

## 一、快速开始

```bash
cd /Users/hatim/src/Workbuddy/lucky
node server.js
```

启动后终端会打印：

```
本机访问   http://localhost:7788
局域网     http://192.168.x.x:7788   （手机扫码用这个）
```

也可以 `npm start`，或执行 `./start.sh` 一键启动并打开主持人台。

首次启动会自动生成一场**演示活动**：60 人名单、5 个奖项、18 人已通过验证，可直接开奖体验。演示名单的姓名与证件后四位可在「名单与奖项」页面查看。

> 手机参与需要与电脑处于**同一局域网**，并允许系统防火墙放行 Node.js。

| --- | --- | --- | --- |
| 活动总览 | `/` | 工作人员 | 活动状态、奖池、参与二维码、各页面入口 |
| 主持人台 | `/host` | 主持人 | 开奖、结束轮次、库存、异常处理、实时动态 |

| 参与者手机页 | `/join?c=活动码` | 参与者 | 身份验证、等待、刮卡、中奖结果 |
| 名单与奖项 | `/import` | 运营 | 批量导入名单/奖项、查看验证状态、导出名单 |

## 三、现场标准流程

1. **创建活动**（系统设置 → 新建活动），拿到 6 位活动码。
2. **导入名单与奖项**（名单与奖项页），支持 `.xlsx` / `.csv` / 直接粘贴，也可下载模板。
3. **开启扫码**（主持人台右上角），活动状态变为「进行中」。
4. **参与者验证**：扫码进入 → 输入**姓名 + 证件后四位** → 通过后进入抽奖池。
5. **主持人开奖**：选择奖项、填写名额 → 点「分配奖项 · 开放刮卡」。
   - 系统当刻从「已验证明单」中随机抽出 N 位，锁定名额并扣减库存；
   - 同时生成抽奖凭证（SHA-256 前 16 位），写入轮次与操作日志。
6. **参与者刮卡**：所有本轮开奖前完成验证的人都会看到刮刮卡；
   - 中奖者刮开显示奖品，大屏同步播放揭晓动画；
   - 未中奖者刮开显示「谢谢参与」，大屏不播报。
7. **结束本轮**：若仍有未刮卡名额，系统会提示并允许作废归还库存，随后结果留档。
8. **领奖与导出**：
   - 「历史报表 → 领奖登记表」生成可直接打印的 A4 签字表，按奖项分组，现场发奖签字用；
   - 主持人台或历史报表 → 导出 Excel（中奖明细 / 奖项汇总 / 轮次记录 / 参与者 / 操作日志）。
9. **开启新一轮**：回到第 5 步即可。

> 开错了奖？主持人台「撤销本轮」可整轮回滚：删除本轮发奖记录、归还全部名额、回收轮次号，原中奖名单会写进操作日志。只能撤销最后一轮。

## 四、核心规则

**先验证，再参与**
只有身份证验通过的人进入抽奖池。开奖后再验证的人不参与本轮（页面会明确提示「下一轮开始即可参与」）。

**名额与库存**
- 开奖时按名额一次性扣减奖项库存，库存不足时无法开奖；
- 作废名额自动归还库存；
- 剩余为 0 的奖项在开奖下拉框中不可选。

**结果不可预知**
- 抽选使用 `crypto.randomInt` 做无偏部分洗牌；
- 抽奖凭证 = SHA-256(轮次 + 时间 + 参与池 + 中奖名单)，可在轮次记录中复核；
- 未刮开的奖项不会下发给前端（防止提前泄露）。

**异常处理**
- **作废**：中奖人不在现场 / 信息有误 / 放弃奖品 → 名额归还库存；
- **补抽**：作废时可勾选「立即补抽一位」，系统从剩余可参与人中再抽一位；
- **撤销本轮**：整轮回滚，删除本轮记录、归还名额、回收轮次号（仅限最后一轮，原中奖名单记入日志）；
- **人工补发**：设备异常、临时嘉宾等场景，主持人可直接指定奖项与参与者补发，记录来源为「人工补发」。

**刷新可恢复**
- 参与者令牌存在浏览器 localStorage，刷新/锁屏后自动恢复当前状态；
- 大屏与控制台通过 SSE 实时同步，断线自动重连并兜底轮询；
- 服务端状态落盘到 `data/db.json`，进程重启不丢数据。

**不重复中奖**
默认「已中奖者不再进入后续抽选池」（可在系统设置中允许重复中奖）。

## 五、名单与奖项导入

**名单列顺序**：`姓名, 证件后四位, 部门/门店, 手机号`

- 证件后四位支持数字或字母，统一转大写；
- 「姓名 + 后四位」组合唯一，重复行自动跳过并在导入结果中提示；
- 覆盖导入会清空当前名单（已有发奖记录时禁止覆盖）。

**奖项列顺序**：`奖项名称, 等级, 数量, 备注`

- 数量为库存总数，导入后仍可单独调整；
- 同名奖项只保留一个。

页面提供「下载模板」，模板内附「填写说明」工作表，可直接在 Excel 中填写后上传。

名单明细支持搜索、编辑、删除与「重置验证」；修改姓名会同步更新已产生的发奖记录，已有中奖记录的参与者需先作废记录才能删除。

## 六、大屏使用建议

- 建议全屏（F11 / ⌃⌘F）打开 `/screen`，分辨率 1920×1080 效果最佳；
- 首次需要点击右上角「开启音效」（浏览器要求用户手势后才能播放声音）；
- 空闲状态右侧会展示大字参与二维码，方便迟到的人扫码；
- 每次揭晓播放动画，点击画面任意处可跳到下一位；
- 多人同时刮卡时会自动排队，队列越长播放越快（4.4s → 2.8s → 1.9s），20 个幸运奖也不会拖几分钟；
- 名字过长会自动缩小字号，不会溢出画面。

## 十、常见问题

**手机扫码打不开？**
确认手机与电脑在同一 WiFi；用启动日志里的局域网 IP（不是 localhost）；macOS 首次运行需在「系统设置 → 网络 → 防火墙」允许 Node 接入；部分企业 WiFi 开启了 AP 隔离，需要改用手机热点。

**大屏没有声音？**
浏览器禁止自动播放，点击大屏右上角「开启音效」一次即可（设置会记住）。

**参与者说没中奖但显示「待揭晓」？**
说明还没刮卡。主持人台「本轮名单」可以看到每个人的状态，也可在结束后统一作废。

**能撤销已经揭晓的奖项吗？**
可以。主持人台本轮名单 → 「异常处理」→ 作废（可同时补抽一位）。已导出过的 Excel 不会自动更新，请重新导出。

**误删了数据？**
`data/db.json` 是唯一数据源，建议活动前在系统设置里下载一份备份；也可靠 `data/db.json.tmp` 之外的定期备份恢复。

**想改成正式活动？**
系统设置 → 新建活动 → 在「活动列表」切换，然后清空或删除演示活动。

## 十一、MVP 边界

当前版本覆盖了完整现场闭环，但以下能力有意留到后续版本：

- 多账号登录与角色权限（目前用单一操作密码保护主持人台）；
- 在线报名、短信/微信通知；
- 与真实身份系统、库存/ERP 对接；
- 多机位大屏同步控制、抽奖过程录屏存证；
- 奖品核销码（扫码核销）与领奖状态跟踪（当前发奖用可打印的签字表登记）。

数据模型已按「活动 / 参与者 / 奖项 / 轮次 / 发奖记录 / 操作日志」设计，扩展这些能力不需要重构。
